# 主站 Schema 应用与同步设计

## 目标

让已审核的 SEO GEO `schemaJson` 能够应用到同一篇兴善堂主站草稿，并在主站公开文章页面以 JSON-LD 输出；不创建重复草稿，也不触发发布。

## 选择的方案

新增“更新已有主站草稿”的受签名 CMS 接口。SEO GEO 只允许针对已经存在的 `(draftId, version)` 主站同步记录调用此接口。主站只更新 Schema 字段，保持文章正文、栏目、状态和发布时间不变。

不采用“再次创建草稿”的方式，避免同一文章产生重复记录；不采用直接修改已发布文章的方式，保持人工发布边界。

## 数据与接口

主站文章新增可空 `schemaJson` 字段。接口 `PUT /api/v1/articles/:id/schema` 接收 `{ schemaJson }`，复用现有 HMAC 认证与随机数防重放机制。

接口要求：

- 文章必须存在且状态为 `draft`；其他状态返回冲突错误。
- `schemaJson` 必须为 JSON-LD 对象，`@context` 为 Schema.org，`@type` 非空。
- 保存前限制对象大小；拒绝数组、脚本字符串和不合法 JSON。
- 返回文章 ID、`draft` 状态与已保存的 Schema 摘要。

## SEO GEO 流程

1. 草稿页提供 Schema 编辑与本地校验；保存生成新草稿版本。
2. 只有当前版本已有主站同步记录时，显示“同步 Schema 到主站草稿”。
3. 调用主站 `PUT` 接口并显示成功／失败，不创建新主站草稿。
4. 无 Schema、Schema 无效、未同步主站或主站文章不再是草稿时，按钮不可用并说明原因。

## 主站输出

主站文章详情页仅在文章已发布且 `schemaJson` 有效时输出一个 `application/ld+json` 脚本。草稿预览与列表页不输出。JSON 序列化会转义 `<`，避免脚本提前闭合。

## 失败处理与验证

- 主站拒绝／网络失败时，SEO GEO 不修改其本地 Schema，也不新增同步记录。
- 使用 409 明确提示主站文章已发布或状态变更，避免覆盖。
- 测试覆盖：JSON-LD 校验、签名请求、仅更新指定草稿、已发布拒绝、详情页 JSON-LD 输出与脚本转义。
- 部署采用现有蓝绿切换；健康检查通过才切换 SEO GEO，主站保留 PM2 重载前后健康检查。
