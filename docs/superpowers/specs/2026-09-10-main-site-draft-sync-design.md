# 主站草稿同步设计

## 目标

让 SEO GEO 中经过人工审核的内容草稿，可由具备内容写入权限的成员显式同步到兴善堂主站的文章草稿箱；同步动作绝不把文章公开发布。

## 现有能力与边界

- 主站已提供受 HMAC 保护的 `POST /api/v1/articles` 接口；该接口无论请求中的状态为何都只创建 `draft` 文章。
- 主站 API 需要 `title`、`slug`、`section`；主站已配置的栏目包括「六壬文化」。
- SEO GEO 生产环境已经保存主站 API 地址、客户端 ID 和密钥配置，不能在页面、日志或数据库审计详情中暴露密钥。
- 主站既有后台仍是文章的最终编辑、预览、删除和正式发布入口。

## 用户流程

1. 成员在 SEO GEO 打开未归档的内容草稿。
2. 页面显示「同步到主站草稿」操作，默认栏目为「六壬文化」；成员可从主站允许的栏目中选择其它栏目。
3. 成员确认后，SEO GEO 使用 HMAC 签名向主站创建文章，主站返回一个新的草稿文章 ID。
4. SEO GEO 记录这次同步的草稿版本、主站文章 ID、栏目和时间，并显示「已同步到主站草稿」及主站后台编辑链接。
5. 主站文章保持 `draft`，只有用户在主站后台手动发布才会公开。

## 数据映射

| SEO GEO 内容草稿 | 主站文章字段 |
| --- | --- |
| `title` | `title` |
| `slugCandidate` | `slug` |
| 用户选择的栏目，默认「六壬文化」 | `section` |
| `excerpt` | `summary` |
| `body` | `body` |
| 固定 `false` | `isPinned`、`isRecommended`、`membersOnly` |
| 固定 `draft`（由主站再次强制） | `status` |

主站现有 API 没有独立的 Meta 标题、Meta 描述或 Canonical 字段；这些字段继续保留在 SEO GEO 草稿中，不伪造为主站字段。

## 同步、重复与冲突规则

- 同一 SEO GEO 草稿版本只能成功创建一次主站草稿；重复点击返回已记录的同步结果，不创建第二篇文章。
- 草稿编辑产生新版本后，可以再次同步；每个新版本创建一篇新的主站草稿，不覆盖旧文章。
- 同 slug 的既有主站文章不会被更新或覆盖。主站返回 slug 冲突时，SEO GEO 显示明确错误并保留原草稿，不进行重试写入。
- 仅在主站确认返回 `201` 和文章 ID 后，才持久化成功记录。
- 网络失败、认证失败、超时、校验失败和主站 `4xx/5xx` 都记录为可读失败状态，可人工再次尝试；不得把失败误标为已同步。

## 安全与权限

- 同步路由要求登录、项目成员资格、CSRF 校验和 `CONTENT_WRITE` 权限。
- HMAC 使用主站既有规范：`METHOD`、路径、毫秒时间戳、随机 nonce 与原始 JSON body 的 SHA-256 组成签名串；每次请求使用新 nonce。
- 仅允许配置的 HTTPS 主站 API 基址；配置缺失时页面禁用操作并给出配置提示。
- 响应和审计日志仅保存主站文章 ID、状态码、错误码与安全的请求摘要，不保存密钥、签名或全文 body。

## 组件与接口

- 新增主站 CMS 客户端，负责校验配置、构造稳定 JSON、生成 HMAC、超时处理与响应规范化。
- 新增同步记录表，唯一键为 `(draftId, draftVersion)`，保存目标文章 ID、栏目、成功时间及失败错误码。
- 在内容草稿详情页加入栏目选择与显式「同步到主站草稿」POST 表单；已成功同步的版本显示结果和主站后台链接。
- 增加受保护的 Web POST 端点，并复用现有发布模块的错误处理和权限守卫。

## 验证

- CMS 客户端单元测试：签名输入、配置缺失、超时和非成功响应。
- 集成测试：具备权限的用户能创建并记录主站草稿；无权限或缺失 CSRF 被拒绝；同一版本幂等；新版本可创建新记录；主站失败不写成功记录。
- Web 测试：按钮、栏目默认值、成功提示与失败提示都正确渲染。
- 发布前通过类型检查、完整测试和生产健康检查；用测试草稿验证主站后台中状态仍为 `draft`。

## 不在本次范围

- 从 SEO GEO 自动发布、撤回或删除主站文章。
- 覆盖主站已有文章或以 slug 推断更新目标。
- 在 SEO GEO 中替代主站的文章编辑器、图片上传或正式发布审核。
