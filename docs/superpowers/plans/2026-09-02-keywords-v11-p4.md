# Keywords V1.1 P4 Target URL + Cannibalization Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Add safe Target URL mapping for Keywords and Clusters plus explainable, persisted cannibalization analysis that reuses existing Growth evidence.

**Architecture:** Add additive Target URL mapping and append-only cannibalization snapshot models. Keep URL normalization and risk evaluation pure; put database reads/writes behind focused repositories and invoke them from project-scoped services/routes. The Keywords workbench consumes effective mapping and latest analysis; existing Growth remains the only owner of GSC query/page detection.

**Tech Stack:** TypeScript, Express, EJS, Prisma/PostgreSQL, Zod, Vitest, Playwright.

**Spec:** docs/superpowers/specs/2026-09-02-keywords-v11-p4-design.md

## Global Constraints

- Continue from feat/keyword-v11-p1-p3 in the existing isolated worktree; do not touch the dirty main workspace.
- Do not merge, deploy, execute a Production migration, or mutate Production data.
- Use one additive migration after the existing 48 migrations; never rename/delete existing data structures.
- All writes use authentication, CSRF, project membership, CONTENT_WRITE, strict Zod schemas, project isolation, and existing Keyword lock acknowledgement.
- A Target URL must be an absolute HTTP/HTTPS URL in Project primaryDomain scope and must use existing crawler normalization for comparison.
- Direct Keyword mapping wins. One inherited Cluster URL is effective; multiple distinct inherited URLs are explicitly AMBIGUOUS.
- Reuse persisted Growth KEYWORD_CANNIBALIZATION evidence; do not add a second GSC detector or worker.
- Analysis only recommends; it never executes merge, redirect, canonical, publication, or deletion actions.
- Unknown evidence lowers confidence and produces reason codes; it must not be rendered as invented search/coverage facts.
