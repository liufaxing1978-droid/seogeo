# P0 Platform Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first working SEO GEO platform foundation with project management, PostgreSQL persistence, Redis/BullMQ jobs, feature flags, a consistent EJS admin shell, and health/test infrastructure.

**Architecture:** Start as a modular monolith so boundaries are explicit without premature microservices. The HTTP app, database access, queues, feature gating, and UI shell are separate modules; later P1-P6 work plugs into these interfaces without changing the foundation.

**Tech Stack:** Node.js 22 LTS, TypeScript, Express 5, EJS, PostgreSQL, Prisma ORM, Redis, BullMQ, Zod, Vitest, Supertest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-18-seo-geo-platform-design.md`

## Global Constraints

- System entry domain target is `seo.xingshantang.org`; analyzed project domains are separate data.
- Use a modular monolith for P0.
- Use PostgreSQL as primary persistence.
- Use Redis + BullMQ for asynchronous work.
- IDs are UUIDs.
- Historical audit/score/sample data added in later phases must be append-only by default.
- `AI_VISIBILITY` and related monitoring capabilities are Advanced-plan features and must be enforceable at the API layer.
- Business modules must not call DeepSeek directly; P4 will introduce the AI Gateway.
- UI shell follows the approved dark left navigation + light main workspace layout.
- No P1 crawler, P2 SEO audit, P3 GEO engine, P4 AI Gateway, P5 content engine, or P6 visibility implementation is included in P0.

2. PostgreSQL stores multiple projects with plan level, language, country, timezone, and domain.
3. Project REST and EJS web flows pass automated tests.
4. Feature flags deny `AI_VISIBILITY` for STANDARD and allow it for ADVANCED/ENTERPRISE at the API layer.
5. Redis/BullMQ queue registry exists with the six agreed queue names; visibility execution remains unimplemented until P6.
6. `/health/live` and `/health/ready` distinguish process liveness from dependency readiness.
7. Dashboard clearly shows placeholder metrics as `等待数据`; no fake SEO/GEO metrics are generated.
8. Typecheck, unit/integration tests, build, and Playwright smoke tests pass locally.
9. CI runs typecheck, tests, Prisma migration, and build on every push/PR.
10. No crawler, SEO audit, GEO audit, DeepSeek, content engine, or AI Visibility sampling logic is smuggled into P0.
